# The registry splits — what is installed is shared, where it landed is not

## Problem

`registry/installed.json` is tracked in git, but two of its fields describe one
particular computer:

- `global_path` — an absolute path under a username (`C:\Users\Martin Cayré\…`)
- `installed_at` — when *this* machine installed the item

Every machine therefore rewrote every entry it touched. Two checkouts could not
pull from each other without conflicting line-for-line on a file neither had
meaningfully changed.

Found the concrete way, on 2026-08-21: pulling a checkout forward produced a
conflict in which "upstream" was the `Verdun-10` machine's install state and
"local" was `MSI`'s. Neither was more correct. Worse, the committed file listed
`data-engineer` as installed while it was absent from this machine's disk — the
registry was describing a computer that was not the one reading it.

That is the real cost: not the merge friction, but that a shared file recording
machine state is *wrong on every machine but one*, silently.

## Decision

Split by lifetime, not by convenience.

| file | tracked | holds |
|---|---|---|
| `registry/installed.json` | yes | `name`, `source`, `hash`, `ref`, `commit` |
| `registry/installed.local.json` | **gitignored** | `global_path`, `installed_at`, keyed by name |

The tracked half is exactly the part that is true everywhere — including the
pinned commit SHAs, which are the thing genuinely worth sharing (see
[[decisions/agent-pinning]]). The local half is regenerated by any install and
is never worth a conflict.

**Callers see neither.** `scripts/registry_io.py` exposes `load()` returning the
merged flat shape the registry has always had, and `save()` splits it again on
the way out. `install-agent.py`, `update-agents.py`, and `agent_usage.py` read
and write entries exactly as before. `selfcheck.py` and the SessionStart
suggester hook needed no change at all — they only ever read `name` and
`source`, both of which stay in the tracked half.

## Migration

Legacy files migrate themselves: a tracked entry still carrying the machine
fields is read as this machine's local values, and the next `save()` writes them
to the local file and drops them from the shared one. `uv run --no-project
python scripts/registry_io.py` performs it as a one-shot and reports the count.

Losslessness was verified against the real 14-entry registry before the split
was accepted, not just against fixtures: `load()` after the migration is
byte-identical to the pre-migration file.

## Why `installed_at` counts as machine-local

It is the one judgement call here. `agent_usage.py` uses it to warn that an
agent was installed before the oldest surviving transcript, so "never invoked"
cannot speak for its first weeks. That comparison is against *local* transcripts
— so the date must be the local one, or the warning is computed from another
computer's history and is simply wrong.
